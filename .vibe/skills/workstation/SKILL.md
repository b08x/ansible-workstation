### Role structure (11 roles)

Standard skeleton: `defaults/main.yml`, `vars/main.yml`, `tasks/main.yml`
(dispatcher), `tasks/assert.yml`, `meta/main.yml`, `README.md`. Deviations from
the skeleton: `meta/argument_specs.yml` is present in common, desktop_ui, gpu,
networking, tools, tts, tuning, user and **absent** in containerd, libvirt,
nas; `handlers/main.yml` exists in every role **except** networking, tts, and
user; `tests/` contents vary (tuning and tools ship `inventory` + `test.yml`,
common and networking ship `inventory` only, gpu has no `tests/` directory at
all); tools has no `files/` or `templates/` directory (no `.keep`
placeholders). Only `roles/common/molecule/default/` has a molecule scenario.

- `roles/common`: baseline packages, **hardware auto-detection**
  (`tasks/hardware.yml`), tuned profile, CIS-L2 hardening (`tasks/hardening/{main,auditd,sshd,crypto,limits}.yml`),
  zsh/yadm install, firstboot. Vars: `AlmaLinux.yml`, `Fedora.yml`, `Rocky-9.yml`, `Rocky-10.yml`.
- `roles/tools`: task dispatcher with 10 subtask files (`runtimes`, `transcribe-cpp`,
  `bun`, `go`, `gitflow`, `inxi`, `homebrew` (Fedora-only), `vscode`,
  `flatpak`, `input-remapper`). `intel.yml` has moved to
  `roles/gpu/tasks/intel.yml` (commit e9a6c78) and the coding-agent installers
  (`antigravity`, `claude`, `crush`, `opencode`) have moved to the standalone
  playbooks in `playbooks/agent-harness/` (see `goals/agent-harness-playbooks/`).
  `vars/main.yml` is empty; no distro vars files.
- `roles/gpu`: host GPU compute stacks — `tasks/intel.yml` (oneAPI toolkit +
  Intel graphics) and `tasks/nvidia.yml` (CUDA driver, toolkit, container
  toolkit), both OFF by default, plus per-major distro vars
  (`vars/{AlmaLinux-10,Fedora-43,Fedora-44,Rocky-9,Rocky-10}.yml` + `main.yml`).
- Other roles (`tuning`, `containerd`, `libvirt`, `desktop_ui`, `user`, `nas`)
  carry `vars/{AlmaLinux,Fedora,Rocky}.yml` (only `nas` also carries
  `RedHat.yml`) loaded via the first_found pattern below.

### Play order — `playbooks/workstation.yml`

1. `import_playbook: repositories.yml`
2. "System Provisioning and Common Configuration" (workstations, become) — `common`
3. "System Configuration" (workstations, become) — `tuning`, `gpu`, `networking`,
   `containerd`, `desktop_ui`, `libvirt` (each `roles:` entry carries its own
   `[role, domain…]` tags). `role: gpu` runs with `tags: ["gpu", "system"]`
   immediately after `tuning` (workstation.yml:55-56).
4. "User Workstation Setup" (become: false) — `user`
5. "Host Tools" (become) — `tools` (agent CLIs are no longer installed here;
   `playbooks/agent-harness/` is the deliberate standalone replacement)
6. "Post-flight Execution Assessment and Reboot Verification" (workstation.yml:97):
   `needs-restarting -r` (RedHat family) + `stat /var/run/reboot-required` →
   `system_reboot_required`; optional `pause`+`reboot` only when
   `workstation_prompt_reboot | default(false) | bool` (default false in
   `group_vars/all.yml:23`). Roles signal reboot by touching
   `/var/run/reboot-required` (see `roles/common/handlers/main.yml`
   "Flag system reboot required").

`local.yml` (ansible-pull): two plays — root "System Provisioning" (role
includes gated by `auto_enable_*` facts where noted) and unprivileged "User
Provisioning" (`user` role). Play 1 includes `common`, `tuning`, `gpu`
(`include_role: gpu`, tags `["gpu", "system", "assert"]`, right after tuning),
`networking`, then `containerd` / `libvirt` / `desktop_ui` (each gated by its
`auto_enable_*` fact), then `tools`; every Play-1 tag list carries `gpu`. It
duplicates the CUDA/Vulkan PCI probes in its pre-flight block and sets
`has_cuda_device` / `has_vulkan_device` — note these names differ from common's
`has_cuda` / `has_vulkan`.

## Variable Scoping

Full rules in `docs/variable-precedence.md`; `var-naming[no-role-prefix]` is
deliberately skipped in `.ansible-lint`.

- **Tier 1 (host/domain scope, unprefixed)** — defined in
  `inventory/group_vars/*.yml` / `host_vars/*.yml`: `user.*` (name, home, shell,
  uid/gid, secondary_groups — SSOT for the workstation user),
  `enable_desktop`, `use_containers`, `use_kvm`, `enable_third_party_repos`,
  `workstation_prompt_reboot`, `user_uv_python_version`,
  `osbuild_{base,group,host}_components` / `osbuild_components`. Tier 1 GPU
  flags consumed by roles/gpu: `intel_oneapi_install` (set on tinybot) and
  `nvidia_cuda_install`. Do NOT prefix these.
- **Tier 2 (role scope, `<role>_*` prefixed)** — role `defaults/main.yml` and
  `vars/main.yml`. Feature-flag dialect is
  `<role>_<feature> | default(false|true) | bool` gating every
  `include_tasks` in the dispatcher. Tier 2 defaults may lazily consume Tier 1:
  `gpu_install_intel_oneapi: "{{ intel_oneapi_install | default(false) | bool }}"`
  (roles/gpu/defaults/main.yml:13).
- **Registered variables** — MUST be prefixed; in practice they use a leading
  underscore: `_tools_effective_uid`, `_common_gpu_vendor_stat`,
  `_common_effective_uid`, `_reboot_check_rhel` (playbook-level `_preflight_*`
  in local.yml). AGENTS.md documents the rule as `<role>_*`.
- **Cross-role facts exported by `roles/common/tasks/hardware.yml`** (tagged
  `always`): `detected_gpu_vendor` (nvidia/amd/intel/none via PCI sysfs probe),
  `has_cuda`, `has_vulkan`, `is_virtual_guest`, `detected_chassis_type`,
  `recommended_tuned_profile`. Any role depending on these must run after
  `common` and declare the dependency (`meta/main.yml` / documented contract /
  Tier 1 inventory) per failure-point 18. `roles/gpu` tolerates
  `detected_gpu_vendor` being undefined: its assert re-probes PCI sysfs when
  the fact is missing (`roles/gpu/tasks/assert.yml:79-104`,
  `when: detected_gpu_vendor is not defined`) and resolves `_gpu_vendor` from
  the probe output.
- **Precedence chain**: role defaults < group_vars < host_vars < extra vars.
  Never reference, in `defaults/`, a variable set later via `set_fact` in the
  same role (lazy evaluation; failure point 17).

## Conventions

### Task Dispatcher Pattern

`tasks/main.yml` opens with a "Starting <role> tasks" debug (tagged
`["<role>", "always"]`), includes `assert.yml` first, then one
`include_tasks: <feature>.yml` per subtask file, each gated by
`<role>_<feature> | default(bool) | bool` and tagged with feature tags plus the
role tag. Ends with `meta: flush_handlers` tagged `always` (common, gpu,
tuning — e.g. roles/gpu/tasks/main.yml:42).

### Pre-flight Assertions (Fail-Fast Pattern)

Every role has `tasks/assert.yml`, included from `main.yml` under
`<role>_assert_enabled | default(true) | bool`, tagged
`["<role>", "assert", "always"]` (standalone: `--tags assert` or
`tasks_from: assert.yml`). Standard assertions: facts gathered
(`ansible_os_family`/`ansible_distribution` defined), OS family `RedHat`,
distribution in `['Fedora', 'AlmaLinux', 'Rocky', 'RedHat', 'CentOS']`,
package manager in `['dnf', 'dnf5']`, effective root via `id -u`
(register `_role_effective_uid`, `check_mode: false`), and role identity vars
(e.g. `user.name`, `tools_user`/`tools_user_home`).

### Tags

Playbook-level domain tags per role: `common`, `tuning`, `gpu`, `networking`,
`containerd`, `libvirt`, `desktop_ui`, `desktop`, `user`, `tools`, `system`,
`virt`, `repos`. `assert` selects all assertion tasks; `always` on
assertions, hardware detection, start/flush debug tasks and fact-gathering
pre_tasks. Feature tags on subtask includes (e.g. `intel`, `intel_oneapi`,
`agents`, `flatpaks`, `homebrew`). The gpu role carries its own domain tag
(`gpu`) plus `system`.

### Handlers

- Handler names prefixed by role context; cross-file notification via
  `listen:` strings (`"restart sshd"`, `"flag reboot required"`,
  `"restart tuned"`, `"daemon reload"` in common; `"Daemon reload"` in tools).
- Reboot signaling: handlers `listen: "flag reboot required"` touch
  `/var/run/reboot-required`, which the post-flight play reads. Roles never
  call `ansible.builtin.reboot` themselves (only workstation.yml's post-flight
  play may, gated by `workstation_prompt_reboot`).
- `ignore_errors: "{{ ansible_check_mode }}"` on service-restart handlers
  (tuning) so check-mode runs stay green.

### Backup-on-write & idempotency

`backup: true` on file edits (e.g. sudoers). Skip-if-present guards ship with
matching `*_force_install` overrides (`gpu_intel_oneapi_force_install`,
`gpu_nvidia_force_install`, `tools_bun_force_install`,
`common_yadm_force_install`). Single ownership: each managed file has exactly
one owning role — grep for other writers before templating a shared path
(failure point 2).

### Human-readable failures (block/rescue)

Mutating task groups use `block:` / `rescue:` where the rescue prints a
human-readable diagnostic then conditionally fails (see
`roles/gpu/tasks/intel.yml`, common package install).

### Distro-specific vars loading

```yaml
- name: Include distribution package variables
  ansible.builtin.include_vars:
    file: "{{ <role>_distro_vars }}"
  vars:
    <role>_distro_vfile: "{{ ansible_distribution }}-{{ ansible_distribution_major_version }}.yml"
    <role>_distro_vars: >-
      {{ lookup('ansible.builtin.first_found',
                files=[<role>_distro_vfile, ansible_distribution ~ '.yml'],
                paths=role_path ~ '/vars') }}
```

`roles/common/tasks/main.yml` (the "Include distribution package variables"
task, line 29) is the reference (tuning adds `'default.yml'` and
`errors='ignore'`). `roles/gpu` implements this shape with per-major files
`AlmaLinux-10.yml`, `Fedora-43.yml`, `Fedora-44.yml`, `Rocky-9.yml`,
`Rocky-10.yml` under `roles/gpu/vars/` (plus `vars/main.yml`), loaded only
when `gpu_install_nvidia` is enabled (roles/gpu/tasks/main.yml).

### Firewall & ports

`ansible.posix.firewalld` rules are co-located in the role/task that needs
them; there is no central firewall role.

### Commits

Atomic, one logical change per commit, subjects shaped
`emoji type: summary` (`✨ feat:`, `🔧 chore:`, `📝 docs:`) per
`docs/conventions.md`.

## Verification

```bash
# Syntax
ansible-playbook playbooks/workstation.yml --syntax-check
ansible-playbook local.yml --syntax-check

# Fail-fast assertions only, mutating nothing
ansible-playbook playbooks/workstation.yml --tags assert --check

# Lint (repo root; .ansible-lint applies)
ansible-lint
#   skip_list: var-naming[no-role-prefix]
#   exclude_paths: .ansible/, vendor/, collections/...
#   extra_vars: target: localhost  (for playbooks/remediate.yml in the llmops repo)
ansible-lint roles/gpu          # per-role check (gpu exists; works today)

# Pre-commit (black/isort/flake8/prettier/ansible-lint + vagrant validate)
pre-commit run --all-files

# Molecule (only roles/common/molecule/default exists)
molecule test -s default   # from roles/common

# Check-mode convergence evidence (used by the goals/gpu-role plan)
ansible-playbook playbooks/workstation.yml --check
ansible-playbook playbooks/workstation.yml --tags gpu   # second real run ⇒ changed=0
```

`.ansible-lint` exists (skip_list, exclude_paths, extra_vars) but has **no
`kinds`/`warn_list` custom profile** beyond the above. CI:
`.github/workflows/tests.yml` runs the ansible-lint action plus a molecule
matrix — the matrix still lists role `base` (tests.yml:27), which no longer
exists (stale).

**Caution**: `ansible.cfg` enables jsonfile fact caching
(`/tmp/ansible_cache`, 86400s) — cached facts can mask fresh
`detected_gpu_vendor` between runs during verification.

**Caution**: the `rich_ci_formatter` stdout_callback emits no
`PLAY RECAP … failed=N` line — verify check-mode runs by exit code /
absence of `FAILED` entries rather than recap greps (`llm_analyzer` is
commented out in `ansible.cfg` and inactive).

## Layer Boundaries

- **Layer 1 (Ansible, this repo)**: system packages via `dnf`, root-owned
  binaries in `/usr/local/bin`, `/etc` configuration, systemd services,
  user-scoped *executables* in `~/.local/bin` / `~/go/bin`.
- **Layer 2 (Yadm dotfiles)**: owns `$HOME` config — dotfiles, `~/.gemini/`,
  `~/.claude/`, `~/.config/`, API keys, agent skills. Ansible roles install
  binaries but do not write user configuration files.
- **Sibling repos (Syncopated)**: `osbuild` (image building, `composer_cli`,
  blueprints, NVIDIA `nvidia` component reference source), `rpmbuild` (RPM
  packaging), `llmops` (dify/langfuse/hermes/ ollama + remediate plugin
  pipeline). This repo references the osbuild component mapping (`osbuild_*`
  vars) but does not build images; the `vars/packages/*.yml` taxonomy is
  generated and consumed within this repo.
- **Role ownership (gpu)**: `roles/gpu` owns all Intel oneAPI + Intel graphics
  and NVIDIA provisioning — `tasks/intel.yml` (Intel graphics drivers, oneAPI
  yum repo, GPG key, pinned MKL/compiler list, `/etc/profile.d/intel-oneapi.sh`)
  and `tasks/nvidia.yml` (CUDA driver, toolkit, container toolkit) — gated by
  `gpu_install_intel_oneapi` / `gpu_install_intel_graphics` /
  `gpu_install_nvidia`, which lazily consume Tier 1 `intel_oneapi_install` /
  `nvidia_cuda_install`. `roles/tools` retains ONLY `transcribe-cpp.yml`'s
  probe of `/opt/intel/oneapi/setvars.sh`
  (roles/tools/tasks/transcribe-cpp.yml:192-193, registers
  `tools_oneapi_check`; it detects, never installs). `roles/common` owns
  hardware *detection* only — it sets `detected_gpu_vendor` / `has_cuda` /
  `has_vulkan` and installs no vendor driver packages. Desktop-environment
  stack belongs to `desktop_ui`; NAS to `nas`; audio/tuning to `tuning`.
