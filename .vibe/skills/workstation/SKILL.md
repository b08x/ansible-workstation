### Role structure (11 roles)

Standard skeleton: `defaults/main.yml`, `vars/main.yml`, `tasks/main.yml`
(dispatcher), `tasks/assert.yml`, `meta/main.yml`, `README.md`. Deviations from
the skeleton: `meta/argument_specs.yml` is present in common, desktop_ui, gpu,
networking, tools, tts, tuning, user and **absent** in containerd, libvirt,
nas; `handlers/main.yml` exists in every role **except** networking, tts, and
user; `tests/` contents vary (tuning, tools, containerd, libvirt, nas ship
`inventory` + `test.yml`; common, networking, tts, user ship `inventory` only;
gpu has no `tests/` directory at all); tools has no `files/` or `templates/`
directory (no `.keep` placeholders). Only `roles/common/molecule/default/` has
a molecule scenario.

- `roles/common`: baseline packages (per-distro `common_packages` now include
  the `golang`, `nodejs`, `npm` runtimes), **hardware auto-detection**
  (`tasks/hardware.yml`), tuned profile, CIS-L2 hardening (`tasks/hardening/{main,auditd,sshd,crypto,limits}.yml`),
  zsh/yadm install, firstboot, and — since the 2026-11 bootstrap conversion —
  **`inxi` and `gitflow-avh`** (`tasks/inxi.yml`, `tasks/gitflow.yml`, gates
  `common_install_inxi` / `common_install_gitflow`, both moved in from
  `roles/tools`). Vars: `AlmaLinux.yml`, `Fedora.yml`, `Rocky-9.yml`, `Rocky-10.yml`.
- `roles/tools`: task dispatcher with 3 subtask files (`vscode`, `flatpak`,
  `input-remapper`). The CLI toolchain surface was divested in the 2026-11
  migration: `bun`, the Go decision tree, cargo/crates, GNOME Shell
  extensions, and VS Code extensions moved to `roles/user`; `inxi`/`gitflow`
  moved to `roles/common`; **homebrew was dropped entirely** (task file
  deleted, no dispatcher include, no defaults or argspec entries). The
  GUI-app subtasks (`vscode`, `flatpak`, `input-remapper`) are second-gated
  by `tools_install_gui_apps` (default
  `auto_enable_desktop | default(true) | bool`); `tools_install_vscode` is a
  REAL opt-in (default `false`). transcribe.cpp has MOVED OUT
  entirely — it is now built by `playbooks/transcribe-cpp.yml` (see Standalone
  Playbooks); every `transcribe` artifact is gone from the role (no task file,
  no `tools_install_transcribe` / `tools_transcribe_*` defaults or
  argument_specs entries). `intel.yml` moved to `roles/gpu/tasks/intel.yml`
  long ago; coding-agent installers live in `playbooks/agent-harness/`.
  `vars/main.yml` is empty; no distro vars files.
- `roles/gpu`: host GPU compute stacks — `tasks/intel.yml` (oneAPI toolkit +
  Intel graphics) and `tasks/nvidia.yml` (CUDA driver, toolkit, container
  toolkit), both OFF by default, plus per-major distro vars
  (`vars/{AlmaLinux-10,Fedora-43,Fedora-44,Rocky-9,Rocky-10}.yml` + `main.yml`).
- `roles/user`: unprivileged user-space toolchain role (2026-11 bootstrap
  conversion; absorbed the divested `roles/tools` CLI surface). Dispatcher
  (`tasks/main.yml`) gates, all tagged `[<feature>, "user"]`: `uv.yml`
  (`user_install_uv`), `bun.yml` (`user_install_bun`; installs to `~/.bun`,
  no become), `go.yml` (`user_install_go`; system-first decision tree:
  `/usr/bin/go` probe → DNF `golang` fallback → user-space tarball to
  `~/.local/go` with `~/.local/bin` symlinks), `cargo.yml`
  (`user_install_cargo`; system-cargo decision tree vs
  `user_cargo_min_system_version` → rustup `--no-modify-path` fallback →
  DNF-preferred crates via `user_cargo_crate_dnf_map` with per-crate
  non-fatal `cargo install --locked`), `gnome-extensions.yml`
  (`user_install_gnome_extensions`, lazily consuming `enable_desktop`),
  `vscode-extensions.yml` (`user_install_vscode_extensions`). Skip-if-present
  overrides: `user_bun_force_install`, `user_go_force_install`,
  `user_cargo_force_install` (+ `user_cargo_force_crates`),
  `user_gnome_extensions_force_install`, `user_vscode_force_install`.
  The role has no handlers; registrations use `_user_*`.
- Other roles (`tuning`, `containerd`, `libvirt`, `desktop_ui`, `nas`)
  carry `vars/{AlmaLinux,Fedora,Rocky}.yml` (only `nas` also carries
  `RedHat.yml`) loaded via the first_found pattern below.

## Standalone Playbooks (canonized pattern)

Opt-in playbooks under `playbooks/` that are **not imported by any entry
playbook** (neither `local.yml` nor `playbooks/workstation.yml`) — running the
playbook is the deployment decision. Members: `transcribe-cpp.yml` (the
richest reference implementation), `agent-harness/{antigravity,claude,crush,opencode}.yml`,
`tts.yml` (unprivileged role wrapper — partial member), and `nas.yml` (root
role wrapper — simplest member).

Shared conventions (all present in transcribe-cpp.yml and the agent-harness
suite; tts.yml follows the unprivileged + explicit-setup subset):

1. **Self-documenting header** — a leading `#` comment block documenting run
   examples, variable summary, opt-in status, and privilege model
   (transcribe-cpp.yml carries an extended header covering precedence
   caveats, check-mode safety, layer boundary, and resource-limiting notes).
2. **`become: false` play, per-task become** — the play runs unprivileged and
   only the tasks that genuinely need root escalate (`become: true` on a task).
   transcribe-cpp.yml escalates exactly four tasks: the pre-flight `id -u`
   root check (which doubles as a passwordless-sudo check — the playbook
   requires passwordless sudo), the conditional `dnf` install of cpulimit,
   the install copy into `/usr/local/bin`, and the always-block cleanup.
3. **Explicit setup pre_task** — `gather_facts: false` + a
   `Gather facts as unprivileged connection user` `ansible.builtin.setup`
   pre_task tagged `always`. Rationale (commented in-source): `gathering =
   smart` in ansible.cfg would otherwise reuse cached facts from a root play
   where `ansible_user_dir` is `/root`.
4. **Own variable namespace** — play `vars:` own the playbook's defaults,
   prefixed with the playbook's short name (`transcribe_*`, `claude_*`).
   Precedence caveat (documented in-source): play vars outrank
   group_vars/host_vars, so **overrides are only possible via extra vars**
   (`-e transcribe_*=...`). This is deliberate — the playbook owns its
   defaults.
5. **Fail-fast pre_tasks assertions** — tagged
   `["<name>", "assert", "always"]`, gated by
   `<name>_assert_enabled | default(true) | bool`, runnable standalone via
   `--tags assert --check` (transcribe-cpp.yml asserts facts gathered, OS
   family/distribution, package manager, effective root, and build
   prerequisites).
6. **Skip-if-present guard + `<name>_force_*` override** — a `stat` pre_task
   on the deployed artifact plus a `transcribe_force_build` /
   `claude_force_install` override to force a re-run (the idempotency
   pattern's `*_force_install` rule applied at playbook level).
7. **Layer-2 boundary** — the playbook installs only the
   binary/CLI; user configuration and data (models, MCP/config files) stay
   with Yadm / user space. Nothing writes into `$HOME`.
8. **Check-mode safety** — probes run with `check_mode: false`; the build
   block carries `not (ansible_check_mode)` so `--check` runs are green and
   mutate nothing.

`playbooks/transcribe-cpp.yml` specifics (source-verified at HEAD):

- Hosts `workstations`; builds transcribe.cpp (Whisper transcription CLI)
  from source into `/usr/local/bin/transcribe`; per-run backend selection
  `cuda → sycl → vulkan → cpu` (nvcc probe → oneAPI compiler probe → Vulkan
  hardware probe → CPU fallback).
- **Hardware qualification gates** (both default ON, each skippable with a
  debug notice, never a hard failure): `transcribe_require_min_specs`
  (min 16 cores; min RAM `32 GB × 0.9` via `transcribe_min_cores` /
  `transcribe_min_mem_gb`) and `transcribe_require_gpu` (CUDA or Vulkan
  device presence). The probes honor inbound `has_cuda_device` /
  `has_vulkan_device` when already defined (exported by local.yml's
  pre-flight), otherwise probe locally under `when: has_cuda_device is not
  defined`.
- **oneAPI is probe-ONLY**: `transcribe_oneapi_setvars`
  (`/opt/intel/oneapi/setvars.sh`) is sourced to detect SYCL compilers; the
  playbook never installs oneAPI — installation is owned by `roles/gpu`.
- **Build resource limiting (Addendum A)**: CMake configure + compile run
  under a composed wrapper prefix — `nice -n 19 ionice -c 3` default-ON
  (`transcribe_build_nice_level` / `transcribe_build_ionice_class`; empty
  values omit the segment), `transcribe_build_taskset_cpus` /
  `transcribe_build_cpulimit_percent` opt-in via extra vars. cpulimit is
  dnf-installed (per-task become) only when a cap is requested and the binary
  is absent. In-source caveats document cpulimit's child-escape weakness,
  per-core percent semantics, and ionice's scheduler dependence.

## Play order — `playbooks/workstation.yml`

1. `import_playbook: repositories.yml`
2. "System Provisioning and Common Configuration" (workstations, become) — `common`
3. "System Configuration" (workstations, become) — `tuning`, `gpu`, `networking`,
   `containerd`, `desktop_ui`, `libvirt` (each `roles:` entry carries its own
   `[role, domain…]` tags). `role: gpu` runs with `tags: ["gpu", "system"]`
   immediately after `tuning` (workstation.yml:55-56). NOTE: since
   transcribe.cpp moved to its standalone playbook, there is **no remaining
   ordering constraint between gpu and tools** — the oneAPI/CUDA probe
   consumer is now the standalone playbook, which runs its own probes.
4. "Host Tools" (become) — `tools` (VS Code opt-in, system Flatpaks,
   input-remapper; transcribe.cpp and agent CLIs are no
   longer installed here; `playbooks/transcribe-cpp.yml` and
   `playbooks/agent-harness/` are the deliberate standalone replacements)
5. "User Workstation Setup" (become: false) — `user` (reordered AFTER Host
   Tools in the 2026-11 migration, mirroring `local.yml`'s tools-then-user
   order so user-space toolchains build against freshly installed system
   packages)
6. "Post-flight Execution Assessment and Reboot Verification" (workstation.yml:97):
   `needs-restarting -r` (RedHat family) + `stat /var/run/reboot-required` →
   `system_reboot_required`; optional `pause`+`reboot` only when
   `workstation_prompt_reboot | default(false) | bool` (default false in
   `group_vars/all.yml:23`). Roles signal reboot by touching
   `/var/run/reboot-required` (see `roles/common/handlers/main.yml`
   "Flag system reboot required").

`local.yml` (ansible-pull): two plays — root "System Provisioning"
(role includes gated by `auto_enable_*` facts where noted) and unprivileged
"User Provisioning" (`user` role). Play 1 includes `common`, `tuning`, `gpu`
(`include_role: gpu`, tags `["gpu", "system", "assert"]`, right after tuning),
`networking`, then `containerd` / `libvirt` / `desktop_ui` (each gated by its
`auto_enable_*` fact), then `tools`; every Play-1 tag list carries `gpu`. The
pre-flight block sets `auto_enable_libvirt` / `auto_enable_desktop` /
`auto_enable_containerd` and probes CUDA/Vulkan PCI state, exporting
`has_cuda_device` / `has_vulkan_device` to downstream consumers (currently
only transcribe-cpp.yml, on explicit invocation). The former
`auto_enable_transcribe` set_fact + debug clause has been removed. Note these
names differ from common's `has_cuda` / `has_vulkan`.

## Variable Scoping

Full rules in `docs/variable-precedence.md`; `var-naming[no-role-prefix]` is
deliberately skipped in `.ansible-lint`.

- **Tier 1 (host/domain scope, unprefixed)** — defined in
  `inventory/group_vars/*.yml` / `host_vars/*.yml`: `user.*` (name, home, shell,
  uid/gid, secondary_groups — SSOT for the workstation user),
  `enable_desktop`, `use_containers`, `use_kvm`, `enable_third_party_repos`,
  `workstation_prompt_reboot`, `user_uv_python_version`,
  `osbuild_{base,group,host}_components` / `osbuild_components`. Tier 1 GPU
  flags consumed by roles/gpu: `intel_oneapi_install` (set on tinybot) and
  `nvidia_cuda_install`. Do NOT prefix these. `has_cuda_device` /
  `has_vulkan_device` (set by local.yml's pre-flight) follow the same
  unprefixed exported-fact logic.
- **Tier 2 (role scope, `<role>_*` prefixed)** — role `defaults/main.yml` and
  `vars/main.yml`. Feature-flag dialect is
  `<role>_<feature> | default(false|true) | bool` gating every
  `include_tasks` in the dispatcher. Tier 2 defaults may lazily consume Tier 1:
  `gpu_install_intel_oneapi: "{{ intel_oneapi_install | default(false) | bool }}"`
  (roles/gpu/defaults/main.yml:13).
- **Standalone-playbook scope** — `playbooks/transcribe-cpp.yml` and the
  agent-harness playbooks define their defaults as play `vars:` under their
  own short-name prefix (`transcribe_*`, `claude_*`, …). Play vars outrank
  group_vars/host_vars by design, so the documented override path is
  **extra vars only** (`-e transcribe_force_build=true`). Never add these
  names to group_vars/host_vars — they will be shadowed silently.
- **Registered variables** — MUST be prefixed; in practice they use a leading
  underscore: `_tools_effective_uid`, `_common_gpu_vendor_stat`,
  `_common_effective_uid`, `_reboot_check_rhel`, `_transcribe_stat` /
  `_transcribe_*` / `_claude_*` (standalone playbooks),
  playbook-level `_preflight_*` (local.yml). AGENTS.md documents the rule as
  `<role>_*`.
- **Facts set by standalone playbooks** — `set_fact` names are prefixed with
  the playbook prefix (`transcribe_has_cuda`, `transcribe_has_vulkan`,
  `transcribe_backend`, `transcribe_cmake_args`,
  `transcribe_build_resource_wrapper`, `transcribe_host_cores`, …), keeping
  them leakage-free.
- **Cross-role facts exported by `roles/common/tasks/hardware.yml`** (tagged
  `always`): `detected_gpu_vendor` (nvidia/amd/intel/none via PCI sysfs probe),
  `has_cuda`, `has_vulkan`, `is_virtual_guest`, `detected_chassis_type`,
  `recommended_tuned_profile`. Any role depending on these must run after
  `common` and declare the dependency (`meta/main.yml` / documented contract /
  Tier 1 inventory) per failure-point 18. `roles/gpu` tolerates
  `detected_gpu_vendor` being undefined: its assert re-probes PCI sysfs when
  the fact is missing (`roles/gpu/tasks/assert.yml`,
  `when: detected_gpu_vendor is not defined`) and resolves `_gpu_vendor` from
  the probe output.
- **Precedence chain**: role defaults < group_vars < host_vars < extra vars
  (play `vars:` in standalone playbooks sit ABOVE group_vars/host_vars — the
  reason for the extra-vars-only override rule). Never reference, in
  `defaults/`, a variable set later via `set_fact` in the same role (lazy
  evaluation; failure point 17).

## Conventions

### Task Dispatcher Pattern

`tasks/main.yml` opens with a "Starting <role> tasks" debug (tagged
`["<role>", "always"]`), includes `assert.yml` first, then one
`include_tasks: <feature>.yml` per subtask file, each gated by
`<role>_<feature> | default(bool) | bool` and tagged with feature tags plus the
role tag. Ends with `meta: flush_handlers` tagged `always` (common, gpu,
tuning — e.g. roles/gpu/tasks/main.yml:42). The tools dispatcher's GUI subtasks
add a second gate (`tools_install_gui_apps`, which lazily consumes Tier 1
`auto_enable_desktop`).

### Pre-flight Assertions (Fail-Fast Pattern)

Every role has `tasks/assert.yml`, included from `main.yml` under
`<role>_assert_enabled | default(true) | bool`, tagged
`["<role>", "assert", "always"]` (standalone: `--tags assert` or
`tasks_from: assert.yml`). Standard assertions: facts gathered
(`ansible_os_family`/`ansible_distribution` defined), OS family `RedHat`,
distribution in `['Fedora', 'AlmaLinux', 'Rocky', 'RedHat', 'CentOS']`,
package manager in `['dnf', 'dnf5']`, effective root via `id -u`
(register `_role_effective_uid`, `check_mode: false`), and role identity vars
(e.g. `user.name`; the `tools_user`/`tools_user_home` identity assertions
were dropped from `roles/tools` in the 2026-11 migration — that role now
asserts facts/platform/root only). The standalone playbooks
implement the same gate as pre_tasks blocks with the same tag triple and
`<name>_assert_enabled` gating.

### Tags

Playbook-level domain tags per role: `common`, `tuning`, `gpu`, `networking`,
`containerd`, `libvirt`, `desktop_ui`, `desktop`, `user`, `tools`, `system`,
`virt`, `repos`. `assert` selects all assertion tasks (roles AND standalone
playbooks); `always` on assertions, hardware detection, start/flush debug
tasks and fact-gathering pre_tasks. Feature tags on subtask includes (e.g.
`intel`, `intel_oneapi`, `flatpaks`, and — since the 2026-11 migration — the
`roles/user` feature tags `bun`, `go`, `cargo`, `gnome-extensions`,
`vscode-extensions` plus the `roles/common` feature tags `inxi`, `gitflow`;
the `homebrew` feature tag is GONE with the dropped homebrew support).
`agents` survives only as a
standalone-playbook feature tag (agent-harness tasks); transcribe-cpp.yml
tags everything `transcribe`.

### Handlers

- Handler names prefixed by role context; cross-file notification via
  `listen:` strings (`"restart sshd"`, `"flag reboot required"`,
  `"restart tuned"`, `"daemon reload"` in common; `"Daemon reload"` in tools).
- Reboot signaling: handlers `listen: "flag reboot required"` touch
  `/var/run/reboot-required`, which the post-flight play reads. Roles never
  call `ansible.builtin.reboot` themselves (only workstation.yml's post-flight
  play may, gated by `workstation_prompt_reboot`).
- `ignore_errors: "{{ ansible_check_mode }}"` on service-restart handlers
  (tuning) so check-mode runs stay green.

### Backup-on-write & idempotency

`backup: true` on file edits (e.g. sudoers). Skip-if-present guards ship with
matching `*_force_install` overrides (`gpu_intel_oneapi_force_install`,
`gpu_nvidia_force_install`, `user_bun_force_install`, `user_go_force_install`,
`user_cargo_force_install` (+ `user_cargo_force_crates`),
`user_gnome_extensions_force_install`, `user_vscode_force_install`,
`tools_vscode_force_install`, `common_gitflow_force_install`,
`common_yadm_force_install`; at playbook level: `transcribe_force_build`,
`claude_force_install`). Single ownership: each managed file has exactly
one owning role — grep for other writers before templating a shared path
(failure point 2).

### Human-readable failures (block/rescue)

Mutating task groups use `block:` / `rescue:` where the rescue prints a
human-readable diagnostic then conditionally fails (see
`roles/gpu/tasks/intel.yml`, common package install).

### Distro-specific vars loading

```yaml
- name: Include distribution package variables
  ansible.builtin.include_vars:
    file: "{{ <role>_distro_vars }}"
  vars:
    <role>_distro_vfile: "{{ ansible_distribution }}-{{ ansible_distribution_major_version }}.yml"
    <role>_distro_vars: >-
      {{ lookup('ansible.builtin.first_found',
                files=[<role>_distro_vfile, ansible_distribution ~ '.yml'],
                paths=role_path ~ '/vars') }}
```

`roles/common/tasks/main.yml` (the "Include distribution package variables"
task, line 29) is the reference (tuning adds `'default.yml'` and
`errors='ignore'`). `roles/gpu` implements this shape with per-major files
`AlmaLinux-10.yml`, `Fedora-43.yml`, `Fedora-44.yml`, `Rocky-9.yml`,
`Rocky-10.yml` under `roles/gpu/vars/` (plus `vars/main.yml`), loaded only
when `gpu_install_nvidia` is enabled (roles/gpu/tasks/main.yml).

### Firewall & ports

`ansible.posix.firewalld` rules are co-located in the role/task that needs
them; there is no central firewall role.

### Commits

Atomic, one logical change per commit, subjects shaped
`emoji type(scope): summary` (`✨ feat:`, `🔧 chore:`, `📝 docs:`) per
`docs/conventions.md` (recent history also carries `type(scope)`).


## Layer Boundaries

- **Layer 1 (Ansible, this repo)**: system packages via `dnf`, root-owned
  binaries in `/usr/local/bin` (including `/usr/local/bin/transcribe`,
  installed by the standalone playbook), `/etc` configuration, systemd
  services, user-scoped *executables* in `~/.local/bin` / `~/go/bin`.
- **Layer 2 (Yadm dotfiles)**: owns `$HOME` config — dotfiles, `~/.gemini/`,
  `~/.claude/`, `~/.config/`, API keys, agent skills. Ansible roles and
  playbooks install binaries but do not write user configuration files;
  transcribe-cpp.yml installs ONLY the binary — Whisper models and user
  configuration stay with Yadm / user space.
- **Sibling repos (Syncopated)**: `osbuild` (image building, `composer_cli`,
  blueprints, NVIDIA `nvidia` component reference source), `rpmbuild` (RPM
  packaging), `llmops` (dify/langfuse/hermes/ ollama + remediate plugin
  pipeline). This repo references the osbuild component mapping (`osbuild_*`
  vars) but does not build images; the `vars/packages/*.yml` taxonomy is
  generated and consumed within this repo.
- **Role ownership (gpu)**: `roles/gpu` owns all Intel oneAPI + Intel graphics
  and NVIDIA provisioning — `tasks/intel.yml` (Intel graphics drivers, oneAPI
  yum repo, GPG key, pinned MKL/compiler list, `/etc/profile.d/intel-oneapi.sh`)
  and `tasks/nvidia.yml` (CUDA driver, toolkit, container toolkit) — gated by
  `gpu_install_intel_oneapi` / `gpu_install_intel_graphics` /
  `gpu_install_nvidia`, which lazily consume Tier 1 `intel_oneapi_install` /
  `nvidia_cuda_install`. The ONLY remaining oneAPI/CUDA *consumer* outside
  roles/gpu is `playbooks/transcribe-cpp.yml`, which probes
  `/opt/intel/oneapi/setvars.sh` and `nvcc` purely to select a build backend
  (`transcribe_oneapi_setvars`; registered probes
  `_transcribe_oneapi_check` / `_transcribe_nvcc_check` — detect, never
  install). `roles/tools` is fully out of the GPU/oneAPI business.
  `roles/common` owns hardware *detection* only — it sets
  `detected_gpu_vendor` / `has_cuda` / `has_vulkan` and installs no vendor
  driver packages. Desktop-environment stack belongs to `desktop_ui`; NAS to
  `nas`; audio/tuning to `tuning`.
